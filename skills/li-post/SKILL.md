# li-post

Read [the shared context and approval contract](../li-context/references/context-contract.md) first.

1. Retrieve relevant context and identify the specific true event, insight or opinion.
   If the idea is too thin, ask one focused question; do not invent an anecdote.
2. Identify claims; apply [li-fact-check](../li-fact-check/SKILL.md) and, only when
   external facts need it, [li-research](../li-research/SKILL.md).
3. Apply [li-history](../li-history/SKILL.md): compare topic, angle, hook, anecdote
   and evidence. A new angle on an old topic is welcome; explain meaningful overlap.
4. Read [the 21-hook library](references/hooks.json) when selecting a hook. Offer
   up to three distinct suitable openings and recommend one. A plain observation
   is valid. Never fill a template with invented figures, clients or dialogue.
5. Draft one idea in natural paragraphs. Let voice and substance determine length,
   links, punctuation and close; no unsupported algorithm or virality claims.
6. Gate the actual draft's claims, apply [li-human](../li-human/SKILL.md), and
   recheck facts changed by editing. Return copy-ready text, character count,
   chosen hook (if any), sources/qualifications and unresolved placeholders.
7. Label draft status accurately. Publication is manual and requires human review.
   Log only confirmed publication with the actual date via li-history.

Request only missing current topic evidence after checking project facts, claims and history.
Delegate that public information need to [li-research](../li-research/SKILL.md),
using the shared contract and preserving evidence IDs.
