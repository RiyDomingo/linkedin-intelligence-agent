# li-comment

Read [the shared context and approval contract](../li-context/references/context-contract.md) first.

Read the supplied post and any known author context. If inaccessible, request
text; do not scrape. Choose from datum (only supported), missing case, respectful
disagreement, extension of a quoted line, real question, actual experience,
factual correction, reframe or a concise one-liner. Give two different options
and a brief recommendation, usually two to four sentences, one substantive point.
Avoid generic praise, repeating the post and invented shared experience. In a batch,
return one tailored comment per supplied post. Apply li-fact-check and li-human
before delivery. Consult comments history for repeated outreach when relevant;
record only confirmed sent comments. All posting remains manual.

When richer context exists, use [li-read](../li-read/SKILL.md) and curated relationship
records for author, thread, expertise, current projects and prior interactions.
Check confirmed comment history before recommending repetitive engagement. If no
substantive contribution or response is needed, return NO RESPONSE NEEDED rather
than forcing two comments. Mark old/undated source material and don't create urgency.

Request facts only when the supplied post and relationship context cannot support a substantive comment.
Delegate that public information need to [li-research](../li-research/SKILL.md),
using the shared contract and preserving evidence IDs.
