# li-profile

Read [the shared context and approval contract](../li-context/references/context-contract.md) first.

Use li-read to retrieve a fresh-enough account profile before asking for supplied
sections. Read observed profile sections and [the 12-part rubric](references/rubric.json).
Score each observed item with evidence and points lost. Mark unseen items
unassessed; report assessed subtotal and possible points rather than scoring
absence of input as absence of a feature. Fix in descending points lost: headline
options, About opening/body, Featured recommendations, experience and banner copy.
Use public evidence; a number is never required. Verify platform limits only when
necessary, or label a proposed limit as a drafting budget. Apply li-fact-check
and li-human. Re-score only changes the draft can substantiate; it cannot create
recommendations, activity or a photograph. Return a table and copy-ready sections.

Prefer actual current profile data through [li-read](../li-read/SKILL.md), then
exports/saved snapshots, then supplied text. Show source and last refreshed date;
unavailable fields remain unassessed. Check consistency with current projects,
stale claims and duplicate positioning. Separate factual corrections from subjective
editorial advice. No LinkedIn profile editing is performed.

Use li-read or supplied profile content first; request external evidence only for a specific public factual gap.
Delegate that public information need to [li-research](../li-research/SKILL.md),
using the shared contract and preserving evidence IDs.
